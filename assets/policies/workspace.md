# 工作目录与材料生命周期

适用于 spec、plan、build、verify、archive。每次进入阶段先读取本文件；以下约束不扩大用户授权，也不替代宿主的权限机制。

- 区分会话目录、目标项目和临时目录。根据用户指定路径或已确认项目确定目标绝对路径，SDD 命令显式设置 workdir/cwd；目标不明先询问，权限不足申请授权或说明阻塞，不切换到其他可写目录另建状态。若流程明确提供隔离 worktree，业务编辑与验证使用该工作区，控制状态的 SDD 命令仍在所属项目执行，不自行重选目录。
- 规格、计划、任务清单、质量报告和归档文档由目标项目 CLI 生成，不直接改写 `.sdd/`，不默认导出副本或在会话目录、仓库内累积 work/、outputs/ 和多版本草稿。用户明确要求导出时遵循授权路径，并说明副本不是第二份权威状态。
- 中间 JSON、核对清单和命令输出优先内存处理；确需落盘时使用安全临时目录机制（如 mktemp -d）在系统临时目录下新建独立任务目录。计划要求的业务文件、项目约定的测试产物和正式交付物不属于这类临时草稿，仍按任务范围处理。
- 清理前确认必要结果和证据已回传、CLI 已接受且后续阶段不再需要该材料。仅按已确认的具体路径清理本任务创建且不再需要的临时材料；失败或暂停时仅保留恢复、复核所需材料并说明位置与用途。用户要求保留的文件不得清理；不得扫描删除其他会话、既有草稿或宽泛目录。
- build 的源代码、测试、迁移和计划内产物不能当临时文件清理；verify 不得在证据回传、复核或故障定位前删除必要日志；archive 仅归档流程状态，不授权删除业务文件、已接受证据、正式文档或归档材料。

这些规则约束宿主行为，不是文件系统沙箱或自动清理器。未得到明确授权，不追溯清理历史任务目录。
